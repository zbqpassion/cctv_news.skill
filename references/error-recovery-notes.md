# 日报漏发、超时与补发流程

## 1. 锁定目标日期与失败环节

1. 用 `TZ=Asia/Shanghai date '+%F %T %Z'` 读取当前时间，再从任务记录确认要补发的绝对日期；跨日或恢复旧会话时不要沿用旧的相对日期。
2. 读取对应任务的配置和最近一次记录，确认执行脚本、参数、目标话题、状态及产物位置；只检查该任务相关日志，不先扩展到全机巡检。
3. 按依赖顺序检查三层证据：
   - **采集**：目标日期原始归档是否有效，央视来源是否匹配。
   - **生成**：任务原始退出码、错误日志与输出正文是否完整。
   - **交付**：目标话题实际发送的是完整日报、部分内容还是失败提示。
4. 把失败发生时间与后续重启区分开；不要把后发生的重启归因为先前的超时。二进制修改时间只能提示继续调查，不能证明升级导致故障。

## 2. 按失败层恢复

### 稿件缺失或缓存无效

- 先读取目标日期缓存，查找 `CCTV.com - ERROR`、`ABSTRACT_NOT_FOUND`、`CONTENT_NOT_FOUND`；错误页可能被当成正常 HTML 缓存，使重试反复读取同一失败内容。
- 列出并检查候选文件后，只删除已确认无效的目标缓存；不要用按日期通配的删除命令清空整批有效页面。
- 在技能目录运行 `/root/.bun/bin/bun scripts/manual-fetch.ts YYYYMMDD`，然后验证摘要、详细新闻、日期、标题及来源；大小只作辅助，不能用固定字节门槛代替内容检查。
- 归档更新后运行 `/root/.bun/bin/bun make-index.ts`，再开展统计与生成。

### 稿件有效但生成超时

1. 先读已有成品、部分输出和进程状态；流式超时不代表文件写入没有发生，已有可校验成品时不要立即重跑。
2. 如需测试生成器连通性，执行一次短提示探测即可；短提示成功只能证明基本调用可用，不能证明完整日报任务一定能跑完。
3. 确认原任务已结束、没有同日期任务仍在执行，再用配置中的生成脚本显式传入目标日期；恢复时不顺带更新 CLI、切换模型或重启网关。
4. 当前 `agy-cctv-news.sh` 支持日期参数时可按下列模式执行。先核对当前实例与脚本接口，再替换 `YYYYMMDD`；这不是无条件适用于其他配置的命令：

```bash
home="${HERMES_HOME:-$HOME/.kiro-hermes}"
target=YYYYMMDD
out="$home/cache/scratch/digest_$target"
bash "$home/scripts/agy-cctv-news.sh" "$target" >"$out.md" 2>"$out.err"
rc=$?
printf 'report_exit_code=%s\n' "$rc"
exit "$rc"
```

5. 在带完成通知的后台任务中执行长生成；用任务句柄检查结果，不另建 `while + pgrep + sleep` 等待循环。进程名匹配可能匹配等待命令自身，导致任务完成后仍空等。
6. 保留生成器本身的退出码；不要让末尾的 `wc`、`printf` 或其他成功命令覆盖失败状态。即使 CLI 返回零，也要检查 `AGY_ERROR`、`DEADLINE_EXCEEDED`、`print timeout`、`returning partial output` 等截断标志，不能把部分输出当成功。
7. 确认未交付成品后，可以做一次受控补跑；再次失败就如实报告阻塞。不要仅凭一次超时建议放宽时间上限，调整须结合完整任务耗时、重叠风险和调度约束另行验证。

## 3. 校验报告，而不只校验进程

- 读取完整候选正文，确认标题日期、固定五节、结尾和正文均完整；非空文件、零退出码和 `success` 日志只能证明某一步执行结束。
- 用 `python3 scripts/check-report.py check YYYYMMDD 报告文件` 把新闻标题顺序、详细报道总数、快讯内条数及链接与原始归档比对；摘要与详细报道不能重复计数。
- 关键数字、发言主体和时间须可追溯到原文。不得以生成报告里的链接和措辞作为其事实已核实的证据。
- 检查研判是否把“部署、支持、强调”升级成“预算已落实、订单必增、估值重塑、息差企稳”；无对应证据就降为有条件推断或删除。

## 4. 历史补报的热词与长期窗口

1. `scripts/trend-analysis.py` 支持 `--until YYYYMMDD`：窗口取截至该日期的最后 N 期归档。补发历史日报时必须带上目标日期，否则会混入之后的新闻。
2. 缺档时最后 N 期不等于连续 N 个自然日。`--summary` 会打印窗口实际起止日期和期数，目标日期没有归档时脚本会给出警告；无法得到正确窗口时明示统计缺失，不伪装成完整近10日或30日统计。
3. 保留实际起止日期与有效天数，缺稿与零命中分开。只使用程序计算的数值，不让模型补齐空缺。
4. 趋势标签按各窗口的日均报道数比较，表格直接给出日均值；沿用脚本的分类结果，不自行换算。
5. 补发日期早于最新登记日期时，`scripts/topics.py set` 会把该日期写成最新登记。补发完成后用 `topics.py show` 核对，必要时按最新一期日报重新登记，避免影响当天任务的沿用基准。

## 5. 交付与沟通

- 请求补发时，先给一两句已核实的故障与恢复状态，再发送通过校验的报告；报告本身保持固定首行与五节结构，不夹带巡检日志。
- 发送后核对目标话题与实际正文；仅有 `delivered`、message ID 或定时任务启用状态，不足以证明用户收到完整日报或下一次任务不会失败。
- 同一产物已经发送后，后台完成通知只用于内部去重，不再次向用户发送确认消息或重复报告。

## 时间实现注意

需要生成北京时间日期时，显式使用 `Asia/Shanghai` 时区格式化；不要把本地时间再手动加八小时，以免重复偏移造成日期跨日。检查日期字符串符合 `YYYYMMDD` 后再传入抓取和生成脚本。
